# OpenMX 基础知识

**适用环境：输入与分析通用；Linux + PBS 运行计算，Windows/macOS 可进行建模与后处理。**

初次阅读可先看软件定位与文件规则，再按“[局域轨道方法应怎样理解](#局域轨道方法应怎样理解) → [用甲烷读懂输入结构](#用甲烷读懂输入结构) → [周期材料的一般计算路线](#周期材料的一般计算路线) → [资源与运行检查](#资源与运行检查)”学习；已有运行经验时，可直接查并行、内存与排错部分。

## 软件定位、方法与任务

OpenMX 是面向材料和纳米体系的开源 DFT 软件，采用局域数值伪原子轨道（PAO）与赝势。轨道有有限空间范围，有利于构建局域矩阵和部分大体系算法；它不是平面波程序，也不是仅用于磁性的工具。

| 类型 | 常见任务 |
| --- | --- |
| 基态 | 单点、结构/晶胞优化、MD、DFT+U |
| 电子与磁性 | 能带、DOS、电荷、共线/非共线磁性、SOC |
| 扩展分析 | NEGF 输运、拓扑/Berry 相关分析、磁性交换参数接口等 |

优势是局域轨道、磁性与输运功能的结合；局限是基组截断半径、轨道数量和赝势选择需仔细测试，局域基组还可能有基组重叠误差。O(N) 方法有适用条件，不代表所有金属和所有任务都会线性加速。与 [VASP](../../VASP/基础与准备/VASP基础知识.md)、[QE](../../Quantum%20ESPRESSO/QE基础知识.md) 对比时，应比较收敛后的物理量，不能只比较一个截断能数字。功能和方法入口见[官方手册](https://www.openmx-square.org/openmx_man3.9/node1.html)。

## 输入规则与 PAO/VPS 数据

主输入一般命名为 `.dat`。普通关键词写在一行；多行块使用 `<名称` 开始、`名称>` 结束，和 CP2K 的 `&END` 不同。`#` 可用于注释。推荐显式写坐标和晶格单位。

| 关键词/数据 | 含义 |
| --- | --- |
| `System.Name`、`System.CurrrentDirectory` | 输出前缀和工作路径；后者拼写确有三个连续 r |
| `DATA.PATH` | PAO/VPS 数据库位置 |
| `Definition.of.Atomic.Species` | 每个类型的 PAO 轨道规格与 VPS 势名 |
| `Atoms.SpeciesAndCoordinates` | 编号、类型、坐标及初始上下自旋电子数 |
| `Atoms.UnitVectors` | 晶格；周期性模型也用于孤立体系的大盒近似 |
| `scf.*`、`MD.*` | 电子计算与原子运动 |

例如 `C6.0-s2p2d1` 中，`6.0` 表示轨道截断半径的 bohr 数，`s2p2d1` 表示各角动量通道的径向函数数目，不是原子电子组态。实际基组名称需存在于选定数据库；赝势名还应匹配泛函、价电子及是否包含 SOC 信息。`scf.energycutoff` 控制实空间积分网格，单位 Ry，并非 VASP 的平面波轨道 `ENCUT`。格式细节见[关键词](https://www.openmx-square.org/openmx_man3.9/node21.html)与[基组手册](https://www.openmx-square.org/openmx_man3.9/node25.html)。

## 一般流程与辅助建模

1. 从同版本官方示例复制最接近的任务骨架，用 ASE/VESTA 准备结构并核对转换。
2. 确认 `DATA.PATH`、轨道/势名、价电子数、初始自旋和晶格单位。
3. 分别收敛 PAO 半径/轨道数、积分网格、k 点和 SCF。
4. 优化后进行能带、磁性或输运任务，保留对应的重启和分析文件。

OpenMX 4.0 提供 [cif2omx](https://openmx-square.org/openmx_man4.0/s8_3_gen-dat-files.html)，可从 CIF 生成 `.dat` 骨架；它不能替代对自旋、基组和目标任务的设置。其他转换工具生成坐标后，也应核对 OpenMX 的自旋电子列与物种定义。磁性交换映射可结合 TB2J，再把自旋模型交给 Vampire；这一步引入模型和采样假设，不等于直接由 DFT 得到有限温度磁性结论。见[本仓库磁性工具笔记](OpenMX与磁性计算工具安装.md)。

## 版本类型、并行与线程

通常都叫 `openmx`，串行、MPI、MPI/OpenMP 是构建差异，不按磁性功能分成 `std/ncl` 三个统一名称。输出和编译配置比文件名更可靠。

已分配 8 个核，混合构建可采用：

```bash
export OMP_NUM_THREADS=2
mpirun -np 4 openmx system.dat -nt 2 > system.std 2>system.err
```

`-nt` 指每个 MPI 进程的 OpenMP 线程数；未指定时通常为 1。MPI 布局与 Band、Cluster、O(N)、NEGF 等求解方式有关，并非任意增加进程都会提速。BLAS 若另开线程，还需避免嵌套超额并行。参考[官方混合并行](https://www.openmx-square.org/openmx_man3.9/node85.html)。

## 内存与输出控制

没有可当作 ORCA `%maxcore` 使用的通用作业内存预算。内存与局域轨道数、邻居范围、k 点、自旋和矩阵分布有关；线程共享部分数据可能减少复制，但应按实际求解器测试。先查 PBS 内存退出和程序的资源信息，再决定是否改变并行布局；减少基组或半径会影响精度，不能当成无代价的内存优化。

`level.of.stdout` 控制终端日志，`level.of.fileout` 控制结果文件详细程度；`MO.fileout` 等进一步控制轨道输出。按需保留密度网格、轨道和矩阵文件，后续 TB2J 等接口可能另有所需。输出规则见[官方 Output files](https://www.openmx-square.org/openmx_man3.9/node22.html)。

## 排错、结果与重启

`system.std` 是启动时重定向的终端记录，`System.Name.out` 汇总 SCF/结构优化等结果；结合相关轨迹和错误输出查看；NEB 还要逐 image 检查相应 `.DFTSCF`，不能只看主进程输出。排错顺序通常是数据文件路径/物种名、单位与原子重叠、自旋电子数、SCF 混合，然后才是并行和数值库。

`scf.restart on` 读取 `System.Name_rst` 中的相容电子状态；应保留相同 `System.Name` 和正确工作路径。它主要解决电子初猜，几何/MD 续算还需恢复结构和相应运动状态，参考[电子重启](https://www.openmx-square.org/openmx_man3.9/node44.html)与同手册的优化重启章节。确认每一步 SCF 和目标任务达到阈值，不能只看生成了 `.out`。

## 局域轨道方法应怎样理解

### PAO 基组的两个收敛方向

平面波程序主要通过截断能增加轨道空间；OpenMX 则需要同时考虑轨道的空间范围和每个角动量通道的径向函数数量。截断半径增大时，轨道覆盖更远的邻居，矩阵可能更密；增加 s/p/d 等函数时，轨道自由度增加，也会提高内存和对角化成本。

例如比较碳基组时，可以先在同一数据库和赝势下逐级增加轨道数量，再测试截断半径；同时独立提高积分网格 `scf.energycutoff`。应比较目标能量差、受力和能带，而不只比较计算总能是否下降。对分子间结合能，局域基组的 BSSE 也是需要评估的来源。

| 选择 | 主要影响 | 建议观察 |
| --- | --- | --- |
| PAO 半径 | 空间覆盖与邻居耦合范围 | 结合、键长、表面/弱相互作用 |
| 径向函数和角动量 | 轨道变分自由度与极化能力 | 能量差、力、局域电子结构 |
| 网格截断 | 积分的数值精度 | 能量、力、平移相关数值噪声 |
| k 点与电子温度 | 周期采样与占据 | 金属总能、磁矩、费米面附近能带 |
| 求解器 | 适用规模、边界和算法近似 | 精度、耗时、内存与任务兼容性 |

### 共线、非共线和 SOC

共线自旋以一个公共量子化轴区分上下自旋，适合许多铁磁/反铁磁初步比较。非共线计算允许局域磁矩方向变化，SOC 则进一步耦合自旋与轨道；二者相关但不等价。没有 SOC 的非共线态和有 SOC 的磁各向异性任务，不能混用能量解释。

原子坐标后的上下自旋数是初始价电子分配。其和应与物种价电子和总电荷设置相容，其差用于建立初始局域磁矩；它们通常不是要求最终每个原子保持不变的约束。多个磁序应分别建立相应初态并比较最终态。

## 用甲烷读懂输入结构

以下采用常见 C/H PBE 数据命名展示单点骨架。先检查数据库实际存在 `C6.0-s2p2d1`、`H5.0-s2p1` 及相应 VPS 名称；`DATA.PATH` 应指向包含 `PAO` 和 `VPS` 子目录的数据根目录。

```text
System.CurrrentDirectory ./
System.Name methane
DATA.PATH ./DFT_DATA19

Species.Number 2
<Definition.of.Atomic.Species
 C C6.0-s2p2d1 C_PBE19
 H H5.0-s2p1   H_PBE19
Definition.of.Atomic.Species>

Atoms.Number 5
Atoms.SpeciesAndCoordinates.Unit Ang
<Atoms.SpeciesAndCoordinates
 1 C  0.000  0.000  0.000 2.0 2.0
 2 H  0.630  0.630  0.630 0.5 0.5
 3 H -0.630 -0.630  0.630 0.5 0.5
 4 H -0.630  0.630 -0.630 0.5 0.5
 5 H  0.630 -0.630 -0.630 0.5 0.5
Atoms.SpeciesAndCoordinates>
Atoms.UnitVectors.Unit Ang
<Atoms.UnitVectors
 15.0  0.0  0.0
  0.0 15.0  0.0
  0.0  0.0 15.0
Atoms.UnitVectors>

scf.XcType GGA-PBE
scf.SpinPolarization off
scf.EigenvalueSolver Cluster
scf.energycutoff 200.0
scf.maxIter 100
scf.criterion 1.0e-7
MD.Type nomd
```

`nomd` 表示此处不做原子运动。`Cluster` 求解器用于此类孤立模型；周期材料应使用适合周期体系的求解与 k 点设置，而不是照搬分子输入。C 初始上下自旋各 2、每个 H 各 0.5，对应中性闭壳层的价电子初猜。盒子足够大与否仍需检查分子镜像影响。

这个例子用来解释字段关系；随安装版本可直接对照[官方甲烷输入](https://openmx-square.org/openmx_man4.0/s8_1_example-methane-molecule.html)和[4.0 关键词表](https://openmx-square.org/openmx_man4.0/s8_2_keywords.html)。不同数据库的文件名不能凭元素名自行推断。

## 周期材料的一般计算路线

### 从优化到电子结构

先检查初始晶胞、原子顺序和磁态，完成基组、网格与 k 点收敛，再优化需要放开的自由度。以优化后结构做 SCF，保留其输出和电子状态，然后计算能带、DOS 或导出矩阵。高对称路径通常来自晶体对称性工具，路径标签必须与实际使用的晶胞一致。

| 目标 | 前置条件 | 结果检查 |
| --- | --- | --- |
| 能带 | 收敛电子态、正确倒空间路径 | 费米能参考、自旋通道、带数 |
| DOS/PDOS | 足够密的采样与投影设置 | 积分、展宽、局域基组投影的含义 |
| 磁能比较 | 相同结构/精度或明确的弛豫方案 | 最终磁矩是否仍对应目标磁序 |
| TB2J 交换参数 | 合适的电子态与接口所需矩阵 | 自旋模型约定、符号、单位和收敛 |
| NEGF 输运 | 电极、中心区及连接一致 | 电极周期、采样和偏压自洽 |

从交换参数到居里温度还要选择自旋模型和统计方法。不同哈密顿量中 J 的符号、是否包含自旋长度及重复计数约定不同；把数值直接复制到 Vampire 前应先核对模型定义。

### SCF 为什么容易在磁性体系卡住

电荷混合、自旋混合、初始磁矩、电子温度和费米面采样都会影响迭代。若残差周期性震荡，先减小问题规模、确认结构和电子态，再查混合方案；若收敛到不希望的磁态，应尝试合理的初态而不只是收紧阈值。金属展宽有助于求解，但过高电子温度可能改变磁矩及能量差，需要再做收敛比较。

## 资源与运行检查

对同一体系比较 8 MPI×1 线程和 4 MPI×2 线程，记录 SCF 单步耗时及节点总内存。局域基组矩阵随轨道数增长，较大基组不一定能靠增大进程数抵消；不同求解器的并行分布也不相同。

输出重定向的文件名与 `System.Name` 是两套命名：`system.std` 来自 shell，而结果文件前缀来自输入。因此，排错时先确认二者确实对应同一输入和同一次任务。修改 `DATA.PATH` 后，可以在输出中核对实际读取的基组和势，避免环境里同时存在多个数据版本而误用。

### 先看哪些文件

| 对象 | 用途 | 检查重点 |
| --- | --- | --- |
| 终端重定向记录 | 启动、输入读取与运行错误 | 第一处异常和实际并行布局 |
| `System.Name.out` | SCF、能量、结构与目标任务汇总 | 达到阈值而非仅达到最大步数 |
| `System.Name_rst` | 电子重启数据目录 | 目录完整、前缀与版本相容 |
| 几何/MD 轨迹 | 结构演化 | 单位、原子顺序、收敛或平衡 |
| 密度、轨道、矩阵输出 | 可视化与下游接口 | 输出开关及下游所需格式 |

### 重启时保留什么

`scf.restart on` 主要读取电子状态。继续优化时还要明确从哪一个结构开始，是否复用优化器历史；继续 MD 更需要速度和运动状态。若只是把旧坐标导入新任务，它属于结构复用，应重新定义温度、速度或优化设置，不应把它描述为完整动力学续算。

常见失败可以按“文件与名称→结构和单位→电子态→SCF 方法→资源”的顺序定位。缺少 PAO/VPS、拼错块结束标记、原子编号/类型不匹配属于输入问题；内存不足和 MPI 退出属于运行问题，二者不应靠增加 `scf.maxIter` 处理。

## 第三方库与资源

MPI、OpenMP、BLAS/LAPACK、FFT 库是主要数值基础；不同构建可能使用 ScaLAPACK 等附加库。TB2J/Vampire 是后续分析链的一部分，不是 OpenMX 默认内置插件；OpenMX Viewer、XCrySDen、VESTA 用于结构、轨迹与体数据，ASE 可辅助批量处理。

数据和工具以[OpenMX 官网](https://www.openmx-square.org/)、[3.9 手册目录](https://www.openmx-square.org/openmx_man3.9/node1.html)及所用数据库版本为准；安装见[编译笔记](OpenMX编译.md)。
