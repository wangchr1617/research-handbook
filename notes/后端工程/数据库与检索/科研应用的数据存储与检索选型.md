# 科研应用的数据存储与检索选型

一个文献问答系统同时保存账号、文档、解析块、向量、实体关系和回答记录。先明确每种数据的用途、事实来源及更新方式，再决定需要哪些组件。

| 组件 | 适合承担的职责 | 设计时要检查 |
| --- | --- | --- |
| MySQL／PostgreSQL | 权限、任务状态、版本、事务记录 | 约束、隔离、备份与迁移 |
| 文件／对象存储 | 原始 PDF、图片、大型轨迹与产物 | 访问权、哈希、版本与恢复 |
| Elasticsearch | 全文召回、过滤、聚合与搜索展示 | 分词、Mapping、刷新与索引同步 |
| Redis | 缓存、短期协调、限流或队列 | TTL、故障行为与持久化需求 |
| Neo4j | 实体关系和可回溯路径 | 实体消歧、来源与派生关系失效 |
| 向量检索组件 | 语义相近内容的候选召回 | 模型、距离语义、版本和权限范围 |

Elasticsearch 也提供向量能力，关系数据库也有全文搜索扩展；技术能力有交集，选型要比较实际查询、规模与维护成本。RAG 是组织检索材料并生成回答的流程，可以使用其中一个或多个检索组件。

## 从最少组件开始

少量研究笔记可先用关系表保存元数据、文件保存原文，配合现有全文或向量索引。需要更复杂的文本相关性、过滤与聚合，再评估 Elasticsearch。明确的多跳关系问题可以评估 Neo4j；仅有文档关键词搜索时，建图会增加抽取和更新成本。

性能比较固定语料、查询、权限范围与硬件，记录召回、延迟、建索引时间和恢复时间。只比较单次查询耗时容易遗漏刷新延迟、重排成本和同步失败。不同检索后端的 `_score`、余弦分数和距离含义不同，应按统一验证集比较，见[RAG 评估](../../知识工程/RAG检索生成与评估.md)。

## 用科研文档库串起数据流

下面是教学方案：MySQL 保存文档归属、源版本、任务和 outbox；原 PDF 进入对象存储；MinerU 输出结构块；索引 worker 将可搜索片段同步到 Elasticsearch，并保存其来源版本和定位。

查询时先取得用户可访问文库，按范围检索关键词或向量候选，再回源校验文档版本、可用状态和权限。随后读取完整证据，组织回答与引用。加入 Neo4j 后，沿实体关系得到的候选也经过同样的来源与权限校验。

解析状态、向量就绪与关键词索引就绪可以分别记录。只要能够准确说明覆盖范围，系统可以提供受限检索；不能把局部索引完成显示成整库全部可搜索。重算、删除和权限变更都沿稳定文档 ID 与源版本传播。

## 对照 Archeos 与 Alkemie

Archeos 的 [db.py](https://github.com/hfood02/Archeos/blob/275ee9c5edcf4df6c773512d8576cb0010168fd4/backend/archeos/db.py)使用 SQLAlchemy 管理连接与 Session，并为 SQLite 分支设置外键、WAL 和等待配置。它说明框架层与数据库配置如何分工；将连接字符串换成 MySQL 后，仍要验证驱动、迁移、SQL、锁和约束行为。

其文献 [retrieval.py](https://github.com/hfood02/Archeos/blob/275ee9c5edcf4df6c773512d8576cb0010168fd4/backend/extension/mineru/retrieval.py)使用带来源版本的检索范围、词法召回和稠密召回。若迁移到 Elasticsearch，应保留这些范围和版本条件，不能只迁移正文后依赖相关性排序。

Alkemie 的 [vector_store.py](https://github.com/hfood02/Alkemie/blob/f3b7481df6920ab14c30a01e7a48dd565130d430/backend/agents/rag/vector_store.py)使用 FAISS 或 NumPy 后端处理归一化向量，其距离越小越近。切换搜索后端时，需对齐模型、度量与排序语义，并重新评估阈值。更完整的实际模块说明见[知识链路](../../知识工程/Archeos与Alkemie的知识链路.md)。

这里提出的 MySQL 与 Elasticsearch 组合是扩展方案，上述源码入口提供的是可复用的工程约束，不表示两个项目已经采用此部署。

## 数据恢复时按依赖关系检查

先恢复权威数据库和原文件，再恢复解析产物与搜索索引，检查来源版本能否对应。若索引有更新但数据库恢复到了更早时间点，索引中的权限或文档状态可能超前，应重建或对账后开放查询。数据库备份、对象存储备份和索引快照需要共同满足恢复目标，分别“有备份”仍不足以保证应用可用。
