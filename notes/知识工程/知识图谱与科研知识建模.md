# 知识图谱与科研知识建模

知识图谱用实体及其关系组织知识。例如，“论文 A 研究材料 B”“计算 C 使用方法 D”“结果 E 来自计算 C”可以连成网络，让读者沿着关系回溯来源。图中的连通路径表达了已记录的关系；科学解释仍要核对原文、计算条件和关系含义。

## 从问题决定图中放什么

假设希望查询：“哪些采用 PBE 的计算报告了某种材料的带隙，数值与条件是什么？”若只保存 `材料 → 带隙 → 数值`，会丢失结构、方法和单位，也无法表示不同论文的冲突。可将一次结果单独建成实体：

| 实体 | 稳定标识 | 主要信息 |
| --- | --- | --- |
| Paper | DOI 或内部文献 ID | 标题、来源、版本 |
| Material | 内部 ID | 化学组成、结构 ID、相态 |
| Calculation | 计算 ID | 软件版本、泛函、赝势、输入摘要 |
| Observation | 结果 ID | 性质、数值、单位、适用条件 |
| Evidence | 证据 ID | 文档版本、页码、表格、原文定位 |

关系可以是 `Calculation STUDIES Material`、`Calculation PRODUCES Observation`、`Observation SUPPORTED_BY Evidence`、`Evidence IN_PAPER Paper`。同一材料的两个带隙结果对应两个 Observation；按条件比较它们，而不是用后一次导入覆盖前一次。

这是面向查询设计的教学模型。只需管理少量规则时，JSON 或关系数据库也能保存这些字段；频繁进行多跳关系查询时，图表示更容易直接表达问题。

## 实体消歧与科研条件

化学式相同不代表结构相同；“GeTe”至少需要结合晶相、结构来源和样品条件判断。软件名也不能代表完整方法：同样使用 VASP，泛函、SOC、自旋和结构优化条件可能不同。将简称作为别名保存，用稳定 ID 建立引用。

单位应保存原值、原单位及规范化结果。例如原文给出的能量是每原子还是每化学式单元，会影响换算；缺少分母时保留缺失状态。`not_reported`、`not_applicable` 与数值零分别表示不同事实。

把模型抽取的候选关系记为 `proposed`，记录抽取模型、提示词版本和原文片段；经核查再标记为 `reviewed`。模型分数表示抽取器的判断，不等于科学结论成立的概率。删除文献、修订解析或撤销访问时，应沿来源标识更新派生关系。

## 属性图与 RDF 怎样选择

Neo4j 使用带标签、属性的节点和带类型、属性的关系，适合应用内查询。RDF 则以主语、谓语、宾语三元组表达陈述，使用 IRI 标识资源，便于共享词汇与跨库关联；基础定义见 [W3C RDF 1.1](https://www.w3.org/TR/rdf11-concepts/)。

两种模型转换时需明确关系属性、空值、重复关系和标识符的映射。把属性图导出成三列文本，只完成了数据排列，尚未完成语义映射。

## 从一小批资料开始

先选十篇左右、问题范围明确的文献，人工标注一组实体、关系和支持段落，约定哪些字段必填。随后依次检查：实体是否错合并、关系方向是否正确、结果条件是否齐全、来源能否定位。十篇是练习规模，不是推荐的统计样本量。

例如“方法 X 改善性能”必须拆开：改善了哪个指标？与什么对照比较？温度、材料和测量方式是否一致？若原文仅有相关性，图中使用 `ASSOCIATED_WITH`，不要改写成因果关系。带来源和条件的图模型，也为后续 [GraphRAG](GraphRAG与混合检索.md)提供可核对的检索路径。
