# GraphRAG 与混合检索

“哪些文献讨论这个参数？”可以先做文本检索。“同一种材料的不同计算条件如何影响结果？”往往还需要沿材料、计算、观测值与证据之间的关系组织答案。GraphRAG 将图信息用于检索与生成，具体实现取决于问题和图模型。

## 先区分两种用法

一种方式从检索命中的实体出发，沿指定关系扩展邻居，再读取原文证据；适合需要明确关系链的问题。

另一种方式先提取实体关系、划分社区并生成社区摘要，再用于语料整体主题的回答。Edge 等的 [GraphRAG 论文](https://arxiv.org/abs/2404.16130)研究了后一类全局汇总方法，并在特定数据与问题上比较了回答覆盖和多样性；迁移到自己的科研语料仍需独立评估。

Neo4j 可保存实体关系，但图数据库的选择并不决定回答策略。RAG 也可以使用关键词和向量检索而不依赖图；按实体扩展一跳，和预计算社区摘要，是成本与适用问题均不同的方案。

## 一个可检查的混合流程

以下为教学设计，假设已经建好带证据来源的科研图：

1. 将问题解析成材料、方法、性质和条件；保留无法确认的实体候选。
2. 用关键词和向量分别召回片段，先限定用户可访问的文档集合。
3. 从片段关联到稳定实体 ID，再沿白名单关系扩展一至两跳。
4. 为每条候选关系取回原文支持、条件和版本；删除只有名字关联却无支持证据的候选。
5. 按问题重排并组织上下文，生成带片段引用和条件对照的回答。

“一至两跳”只是控制成本的示例，实际预算应同时限制候选实体数、关系数、检索轮数、返回文本量和总期限。实体消歧错误会把不相干的研究连在一起；扩展更多邻居会放大这种错误。

例如问题是“同一材料采用不同泛函时带隙怎样变化”，需要通过材料结构 ID 找计算，再取各自 Observation 和 Evidence。比较前检查结构、自旋、SOC 和带隙定义；条件不一致时列出差异，避免将所有数值直接归因为泛函变化。

## 图摘要也需要来源

社区摘要是从多份证据派生的文本。保存它依赖的文档及版本、生成模型、提示词和访问范围，回答时尽量回到支持片段。共享社区若混入私有文档，即使最终不显示该文档标题，摘要本身也可能泄露信息。

更新一篇文献后，除了删除旧向量，还要更新对应实体、断言、路径缓存和摘要。把这些依赖关系记录下来，比仅给文件标记“已删除”更容易保证派生内容一致。

## 怎样判断图是否值得引入

在同一语料、问题划分、生成模型和上下文预算下，比较关键词、向量、混合检索及加入图扩展的方案。按单篇事实、关系链、跨文档比较与全局汇总分别统计，避免平均分掩盖问题差异。

除 [RAG 的通用指标](RAG检索生成与评估.md)外，还要检查实体链接正确率、关系支持率、路径中每一步的来源，以及建图、摘要更新和在线查询成本。如果图扩展提高覆盖却引入更多无依据关系，先定位实体或抽取错误，再调整扩展范围。

对 Alkemie 的软件参数规则问答，可先用已有向量检索作基线；对 Archeos 的文献资料，可先保留其解析与证据定位链路，再评估图是否补足跨文档查询。这里给出迁移思路，实际已实现模块见[项目链路](Archeos与Alkemie的知识链路.md)。
