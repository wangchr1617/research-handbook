# 知识工程

按学习顺序阅读：[阅读目录](阅读目录.md)。

把论文、软件手册与计算经验变成可追溯的检索和问答服务，需要同时处理文档结构、知识表示、索引与回答证据。本专题从科研资料出发，连接已有的[后端工程](../后端工程/README.md)和[材料数据库](../材料数据库专题/README.md)。

| 阅读入口 | 笔记 | 要解决的问题 |
| --- | --- | --- |
| 1 | [知识图谱与科研知识建模](知识图谱与科研知识建模.md) | 怎样表示实体、关系、实验条件与证据？ |
| 2 | [MinerU 文档解析与质量检查](MinerU文档解析与质量检查.md) | 怎样把 PDF 变成可定位的文本、表格与公式？ |
| 3 | [RAG 检索、生成与评估](RAG检索生成与评估.md) | 怎样找对材料、引用材料并检验回答？ |
| 4 | [Neo4j 与 Cypher 入门](Neo4j与Cypher入门.md) | 怎样保存、更新和查询关系网络？ |
| 5 | [GraphRAG 与混合检索](GraphRAG与混合检索.md) | 什么时候需要沿关系扩展或做跨文档汇总？ |
| 6 | [Archeos 与 Alkemie 的知识链路](Archeos与Alkemie的知识链路.md) | 实际项目怎样组织解析、索引、缓存与权限？ |

可按问题选择入口。初次做文献问答，可按“解析 → 抽查 → 分块 → 检索 → 带引用回答 → 评估”实践；需要回答“某个结果如何关联到材料、方法和来源”时，再引入图建模。Neo4j 是图数据库，MinerU 是文档解析工具，知识图谱是知识表示方式，RAG 是利用检索材料辅助生成的流程，四者可以组合，也可以分别使用。

示例中的论文、项目编号和科研断言均为教学数据。项目实例链接固定到源码提交；接口、命令及外部文档核对日期为 2026-11-07，具体适用版本见各篇说明。

## 数据存储与全文搜索

需要持久保存文档归属、任务和版本时，可阅读[MySQL 建模与 SQL](../后端工程/数据库与检索/MySQL建模与SQL入门.md)；需要为 RAG 提供全文召回、过滤与聚合时，可阅读[Elasticsearch 映射与检索](../后端工程/数据库与检索/Elasticsearch映射与全文检索.md)。二者与向量检索、Neo4j 的分工见[科研应用选型](../后端工程/数据库与检索/科研应用的数据存储与检索选型.md)。
