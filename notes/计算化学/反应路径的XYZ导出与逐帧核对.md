# 反应路径的 XYZ 导出与逐帧核对

**适用环境：通用；普通 XYZ 核对使用 Python / NumPy，可视化可用 VMD 等分子查看器。**

导出轨迹的目的，是让结构、能量和性质继续保持同一帧身份。动画能播放、帧数与能量行数相同，是初步检查；是否包含全部接受点、原子身份是否一致，还要对照原始输出。

## 从哪个文件导出

Gaussian IRC 可使用 [GauIRC2xyz](http://sobereva.com/285)把输出文件转换为同名 XYZ。其说明提供 Windows 和 Linux 可执行版本；按所用系统和版本选择已有工具。它处理的是格式转换，原任务是否完整、重启段是否包含在内、两侧顺序和 TS 是否重复仍需对照原始输出。

ORCA 6.1 已直接提供各方向轨迹及端点 XYZ。双向任务的 `_IRC_F_trj.xyz`、`_IRC_B_trj.xyz` 与完整拼接文件用途不同；downhill 的本例输出为 `_IRC_D_trj.xyz`。几何优化的 `_trj.xyz` 又属于优化历史，不能因扩展名相同就把所有轨迹称为 IRC。

保留原生文件副本，并记录它来自哪个任务、方向、电子态和几何单位。检查点与重启输出也各有范围，不能只按文件创建时间把轨迹串起来。

## 普通 XYZ 能记录什么

每帧包含原子数、注释行和相应行数的“元素符号 x y z”，然后继续下一帧。注释可以为空，通常的 XYZ 也不强制规定坐标单位、时间、能量、晶胞、化学键或原子身份标签。相同元素的两颗原子交换后，元素序列甚至可以保持完全相同。

因此需要另存单位和原子映射；涉及周期轨迹时还需晶胞与连续映像。由查看器自动猜出的键线不是原生计算中的键级。把 0.529177 附近的尺度差误当成结构弛豫，会使后续键长、角度与积分分析一起出错。扩展格式中的晶胞、逐原子字段及普通读取器的支持范围，见 [XYZ 与扩展 XYZ 的字段和单位](XYZ与扩展XYZ的字段和单位.md)。

## 用脚本检查完整帧和几何列

[配套 trajectory.py](../../examples/orca/minimal/scan-and-descent/trajectory.py)读取普通 XYZ，要求显式选择 Å 或 Bohr，拒绝截断末帧、帧间元素序列变化和非有限坐标；保留重复帧，不自动去重。它输出原文件副本、带几何摘要的逐帧 CSV 和清单。编号从 1 开始。

例如在[水分子案例](../../examples/orca/minimal/scan-and-descent/README.md)目录执行：

```bash
python3 trajectory.py downhill.xyz --coordinate-unit angstrom \
  --energy-format orca --expected-frames 19 \
  --bond 1,2 --bond 1,3 --angle 2,1,3 \
  --output-dir /tmp/new-water-frame-audit
```

输出目录应为新目录。`--energy-format orca` 只接受已知的原生 ORCA 注释格式并将其能量解释为 Hartree；一般或由其他程序转换的 XYZ 使用默认 `none`，不会从一行任意数字中猜能量。期望帧数来自本案例的原生接受点表，换任务时要相应修改，不能沿用 19。

**脚本通过后，还要检查什么？** 这个检查不能识别同元素原子的暗中交换，也不解析 Gaussian 日志或恢复漏帧。清单中的摘要用于确认数据对应，不代表电子结构和反应机理已被验证。

## 对齐能量与性质时保留原始身份

建立至少包含“来源任务、支路、接受点编号、几何摘要、扫描坐标、能量字段与单位”的对应表。对相关方法读取相应最终总能，对激发态明确读哪个态；不要把所有 `SCF Done` 行依次配给所有结构。预测/校正点、优化微迭代和最终接受点可能有不同数量。

拼接双向 IRC 时，按几何和源点身份连接两侧，确认 TS 保留规则；能量相等不构成去重条件，反应物和产物也可能对称等价。重启段可能重复接缝点，或只含新增帧。保留原序列与映射，再决定面向某张图怎样展示。

做波函数后处理时，每个任务从相应帧几何重新计算或读取对应波函数，并核对电子态。某一个轨道文件不能只因文件名相似就用于所有帧；转换坐标方向后，相关矢量、外场和波函数约定也要一起考虑。

## 优化动画跳变时先检查坐标方向

Gaussian 输出可能同时包含 `Input orientation` 和 `Standard orientation`。后者是程序采用的标准取向；相邻两步内部几何变化很小，坐标轴的选择仍可能出现翻转或交换。GaussView 读取中间几何后若画面突然转动，先比较跳变前后的键长、键角和对齐后 RMSD，再判断是否发生真实结构变化。

保留原日志，从一致的坐标区块导出独立轨迹，并按固定原子映射做刚体对齐。不要直接把原日志里的 `Standard orientation` 标题批量替换成 `Input orientation`：这会改变区块的含义，也可能影响后续解析。查看器版本与读入设置会影响显示方式，特定旧版的跳变现象不能推广到所有版本。

Gaussian 的 `Geom=PrintInputOrient` 可用于请求更多输入取向信息，具体打印行为按版本和实际输出核对。`NoSymm` 会影响计算中的对称性与坐标处理；只为改善动画时，优先处理派生轨迹，不为显示问题无条件重跑计算。涉及固定外场或实验室坐标方向时，保留原始方向及相关矢量，另存可视化副本。操作和实际轨迹示例见 [RMSD、原子映射与轨迹对齐](RMSD、原子映射与轨迹对齐.md)。

## MOPAC 轨迹先核对优化器与打印内容

MOPAC 输出可用与版本匹配的转换器处理。旧版 [mopac2xyz](http://sobereva.com/212)针对 MOPAC 2012/2016 的 EF 优化轨迹，要求用 `PRNT=2` 打印相应细节，并把输入第三行注释设为 `All coordinates are Cartesian` 作为定位标记。这个文字是该转换器的查找约定，不是所有 MOPAC 任务都必须采用的通用语法。当前 MOPAC 的 [`PRNT=n`](https://openmopac.net/Manual/prnt.html)手册仍将它定义为控制 EF 打印细节的关键词。

转换器能输出多少帧，取决于日志实际打印的内容及解析支持。旧转换器对 L-BFGS 输出可能只能读到首尾结构；先查当前版本的原生轨迹或匹配的解析方式，按体系需求选择优化器。只为播放动画而改成 EF，会改变计算流程和成本，也不能恢复旧日志中从未保存的结构。

抽帧时另存原始步号、采样间隔和最终接受点，检查最后一帧是否保留、重启接缝是否重复。通用 XYZ 核对脚本只检查转换后的完整帧、单位和序列，不解析 MOPAC 日志，也不能从首尾结构重建中间路径。

## 从多帧结构批量生成计算输入

用模板替换几何时，显式保留“源文件、原始帧号、筛选后编号、输入文件、工作目录”的映射。排序后的前几帧仅表示原筛选模型下的能量次序，不保证在目标方法下仍最低。逐项检查电荷、自旋、任务类型、基组／赝势、约束和周期晶胞；普通 XYZ 只提供几何，模板不能从中自动判断这些条件。

独立构型使用独立结果及重启文件，避免同名检查点或自动初猜使任务意外串联；确需沿路径复用电子态时，记录来源并检查态连续性。单文件多步任务中，一步失败可能使后续步骤未执行，汇总时按任务段与正常终止状态关联能量，不按出现顺序收集所有 SCF 行。批量生成输入只是准备步骤，不能把生成成功计作计算完成。

## 在 VMD 里测量时注意编号

VMD 的原子索引从 0 开始。例如已将水轨迹作为当前分子载入时，Tcl 命令为：

```tcl
set m [molinfo top]
set oh [measure bond {0 1} molid $m frame all]
set hoh [measure angle {1 0 2} molid $m frame all]
```

`measure bond` 返回两原子间的几何距离，不依赖是否画出键线，也不返回量子化学键能；指定 `molid` 避免误用另一个当前分子。语法见 [VMD measure 文档](https://www.ks.uiuc.edu/Research/vmd/vmd-1.9.4/ug/node139.html)。

导出的距离、角度与能量曲线仍需明确横轴是帧号、扫描变量还是弧长。IRC/downhill 的帧号通常没有时间单位；反应物、产物方向应按实际几何标注。周期路径另保留逐帧晶胞和原子映像。
