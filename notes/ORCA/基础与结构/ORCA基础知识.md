# ORCA 基础知识

**适用环境：输入与分析通用；Linux + PBS 运行计算，Windows/macOS 使用各自支持的官方安装包。**

ORCA 的输入通常不长，但方法、基组、电荷和自旋的选择会直接影响结果。下面先说明这些设置的含义，再用水分子串起输入、优化和频率分析；并行、内存及重启说明可在运行时查阅。

## 软件定位、方法与任务

ORCA 以分子量子化学为主，覆盖 HF、DFT、MP2、耦合簇、多参考方法和光谱性质。它通常用原子中心高斯轨道展开分子轨道；RI、COSX、DLPNO 等分别对不同计算环节进行近似或局域化，不能混为同一种“加速”。

| 类型 | 常见任务 |
| --- | --- |
| 能量与结构 | 单点、优化、频率、过渡态、IRC、构象研究 |
| 电子激发与光谱 | TDDFT、UV–Vis、振动、EPR/NMR 等 |
| 高精度关联 | MP2、CC/DLPNO-CC、多参考及相应性质 |
| 环境与相对论 | 隐式溶剂、QM/MM、ECP、标量相对论与 SOC 等 |

ORCA 的分子方法与光谱功能较丰富，输入入口也比较直观。使用高阶方法时，需要仔细选择基组与参考态，并准备足够的内存和磁盘；周期材料大规模平面波工作流通常更适合 [VASP](../../VASP/基础与准备/VASP基础知识.md)/[QE](../../Quantum%20ESPRESSO/QE基础知识.md)。涉及界面 AIMD 可对照 [CP2K](../../CP2K/基础与准备/CP2K基础知识.md)。版本、平台和使用条件以[官方手册与下载入口](https://www.faccts.de/docs/orca/6.1/manual/index.html)为准。

## 方法应该怎样选择

### 把结构、能量与性质分层考虑

对中等规模分子，常先用适合体系的 DFT 方法优化并算频率，再用更大基组或更高层级方法算单点。这样可以节约成本，但最终结果需明确写成“某层级单点//某层级结构”，并说明热修正来自哪一层级。不同构象、反应物和产物应采用一致方案。

| 方法/近似 | 解决的主要问题 | 需要检查 |
| --- | --- | --- |
| HF | 单行列式平均场参考 | 缺少动态相关，弱相互作用等常不充分 |
| DFT/杂化 DFT | 成本与精度平衡的结构和性质 | 泛函适用性、色散、自旋与离域误差 |
| 双杂化、MP2 | 引入部分或系统的微扰相关 | 参考态、基组收敛、弱相互作用与近简并 |
| CC、DLPNO-CC | 单参考体系高精度相关 | 单参考适用性、局域阈值、基组与成本 |
| CASSCF 等多参考 | 近简并与多组态电子结构 | 活性空间、态选择、动态相关补充 |
| TDDFT 等激发态 | 垂直激发、部分光谱与激发态任务 | 态性质、电荷转移、溶剂与方法局限 |

RI 是积分拟合类近似，COSX 用于交换计算的近似处理，DLPNO 是局域相关框架。它们优化的是不同环节，不应把“加速后仍叫 DFT”理解为所有结果与设置都相同。具体方法与支持性质应从[对应版本手册](https://www.faccts.de/docs/orca/6.1/manual/index.html)查询。

### 基组、电荷和自旋优先检查

[双 zeta 基组](https://www.faccts.de/docs/orca/6.1/manual/contents/essentialelements/basisset.html)可用于预优化，三 zeta 及更大基组可用于进一步精度检查；阴离子、弥散态、氢键和弱结合常需关注弥散函数。重元素需要相容的 ECP 或全电子相对论方案，不能只在普通基组后随意加一个相对论关键词。

电子数等于核电荷总和减总电荷；多重度为 $2S+1$。闭壳层单重态并不适合所有偶数电子体系，过渡金属还可能存在多个自旋态。检查占据、局域自旋和 $\langle S^2\rangle$，并结合化学问题判断；自旋污染大小也不是判断所有多参考特征的唯一指标。

## 输入规则、基组与 ECP

`!` 行给简写关键词，`%模块 ... end` 给细节，坐标块包含电荷与自旋多重度。例如以下为输入格式示意，引用的 XYZ 需事先准备：

```text
! PBE0 def2-SVP TightSCF Opt
%pal nprocs 4 end
%maxcore 2000
* xyzfile 0 1 molecule.xyz
```

`0 1` 表示总电荷 0、单重态；不是“上下自旋电子数”。坐标可写在 `* xyz ... *` 块中，常用长度为 Å。大多数关键词不区分大小写，但路径和文件名要按实际系统填写，`#` 可用于注释。语法和资源设置见[官方输入说明](https://www.faccts.de/docs/orca/6.1/manual/contents/essentialelements/input.html)。

| 数据类型 | 作用 |
| --- | --- |
| 轨道基组，如 `def2-SVP/def2-TZVP` | 展开轨道；需检查极化、弥散与基组收敛 |
| 辅助基组，如 `/J`、`/JK`、关联拟合基组 | 对应 Coulomb、交换或相关拟合，角色不同 |
| ECP | 以有效芯势替代选定芯电子，需与轨道基组相容 |
| 全电子相对论基组 | 与 DKH/ZORA 等具体哈密顿量配套使用 |

常用基组/ECP 通常通过名称从程序数据库选择，也可自定义；不需要像平面波软件那样为每个分子拼接 `POTCAR`。几何、频率和能量比较应统一方法，弥散态、阴离子与弱相互作用尤其要检查基组和 BSSE。

## 一个可读懂的水分子优化输入

```text
! PBE0 def2-SVP TightSCF Opt Freq
%pal
  nprocs 4
end
%maxcore 2000
* xyz 0 1
O  0.000000  0.000000  0.000000
H  0.757000  0.000000  0.586000
H -0.757000  0.000000  0.586000
*
```

保存为 `water.inp`，使用匹配安装的 ORCA 驱动运行。这里把坐标直接写在文件里，不再依赖外部 XYZ；长度默认按常用 Å 输入。`Opt Freq` 表示先优化后计算频率；该方法组合用于说明流程，不能代表所有体系的最佳方法。

| 输入部分 | 含义 | 容易混淆的地方 |
| --- | --- | --- |
| `! ...` | 方法、基组、精度与任务简写 | 可运行不代表方法适用于目标电子态 |
| `%pal` | 并行进程数 | 不是每个进程再开同样多线程 |
| `%maxcore` | 每处理核心/进程主要内存工作区 | 不是总内存，也不是绝对上限 |
| `* xyz 0 1` | 电荷 0、多重度 1、笛卡尔坐标 | 多重度不是上下自旋电子数之差 |
| 最后 `*` | 坐标块结束 | 与 `%...end` 块结束方式不同 |

单点任务可去掉 `Opt Freq`；读取外部结构可改用 `* xyzfile 0 1 water.xyz`。不要在不同坐标入口之间留下互相矛盾的结构定义。语法见[输入参考](https://www.faccts.de/docs/orca/6.1/manual/contents/essentialelements/input.html)。

## 一般流程与输入辅助

1. 准备构象、质子化、电荷与自旋，必要时比较不同磁态和构象。
2. 选方法、基组、溶剂和资源，先做低成本 SCF/结构测试。
3. 优化后做频率：极小值检查虚频，过渡态检查目标虚频及路径连接。
4. 按任务提高能量层级或计算光谱，分析波函数与实验对应关系。

Avogadro、Chemcraft、官方 GUI/工具接口可辅助建模；Multiwfn 可辅助输入和电子结构分析，CREST/xTB 可用于合适体系的预优化与构象搜索。预优化结果仍应在目标量化方法下复核，不把不同层级的能量混合比较。

## 优化和频率结果怎样解释

### 正常结束、优化收敛和极小值是三件事

先看电子迭代是否收敛，再看几何优化的梯度与位移阈值，最后看频率模式。稳定极小值通常不应有实质虚频；过渡态应有对应目标反应坐标的一个虚频，并通过路径/连接关系验证。很小的虚频可能与数值精度、软模或不充分优化有关，应查看振动模式再判断。

频率计算提供零点能和特定统计模型下的热力学校正。比较自由能时，应统一温度、压力/标准态、溶剂模型和构象处理。溶液反应不能不加说明地把气相标准态热修正直接当作实验溶液自由能；低频柔性模式也可能需要适合的处理。

### 溶剂与构象不可省略

隐式溶剂描述平均环境，不自动包含特定氢键、配位或质子接力。若这些作用主导反应，可考虑显式溶剂分子与连续介质组合，并评估构型取样。xTB/CREST 可辅助搜索构象；最终排序应在目标计算层级及相同环境下复核。

## 可执行程序、并行与线程

主要入口是 `orca`；安装包内的其他程序多为计算模块或辅助工具，不是类似 VASP `std/gam/ncl` 的物理任务三分法。普通 CPU 并行通常由 `%pal nprocs ... end` 或 `PALn` 设置，串行驱动负责启动并行模块。

```bash
# 已申请4个CPU核；程序路径为示意，需替换为实际安装路径。
export OMP_NUM_THREADS=1
/path/to/orca/orca molecule.inp > molecule.out 2>molecule.err
```

不要用 `mpirun -np 4 orca ...` 再包一层 ORCA 驱动。使用完整程序路径，运行时 MPI 版本与安装包要求匹配；设置 `OMP_NUM_THREADS` 并不能代替 PAL 进程设置。不同模块的并行效率不同，数值频率还可能按位移任务分发。细节见[官方并行说明](https://www.faccts.de/docs/orca/6.1/manual/contents/essentialelements/parallel.html)。

## 文件、内存和后处理的具体安排

`%maxcore 2000` 表示每个处理核心/进程的主要工作区预算约 2000 MB，不是整个作业只用 2 GB，也不是严格的 RSS 硬上限。四进程应按约 8 GB 工作区加其他开销估计，并为系统/库留余量；手册建议整体预算不要吃满可用物理内存。单节点多进程尤其要把总和与 PBS 申请内存比较。

关联方法可能产生很大的临时积分/振幅文件，RAM、scratch 容量和 I/O 性能都要考虑。使用独立计算目录，保留所需 `.gbw/.hess/.xyz` 和输出；不能在结果未完整回存前清理 scratch。

| 文件 | 常见用途 | 保存要点 |
| --- | --- | --- |
| `.inp/.out/.err` | 实际输入、结果与故障信息 | 保存完整输出，注明程序版本 |
| `.gbw` | 轨道和波函数相关信息 | 电子初猜与分析常需要 |
| `.xyz` 及优化轨迹 | 最终结构/结构演化 | 明确最终结构对应的任务 |
| `.hess` | Hessian、振动相关信息 | 重用或分析时与结构和方法匹配 |
| 临时积分/关联文件 | 模块工作数据 | scratch 容量可能成为瓶颈 |
| Molden/cube | 波函数与网格分析 | 保留生成方式，检查转换适用性 |

例如节点可供作业使用 32 GB，8 个进程设 `%maxcore 2500`，主要预算约 20 GB，剩余空间容纳其他数组与系统开销；这只是规划起点，应看具体模块峰值。内存不足时可以比较减少进程、增加每进程可用量的方案，而不是同时增加 `%maxcore` 和进程数。

`%output` 中的打印选项与各模块输出开关控制内容；不要为“详细”盲目打开全部矩阵或轨道。轨道分析可用 `orca_2mkl` 转为适合下游的 Molden 数据，密度/轨道网格可用 `orca_plot`，再交给 Multiwfn/VMD 等工具。

在结果目录运行下列工具可生成常见分析输入：

```bash
orca_2mkl water -molden
orca_plot water.gbw -i
```

第一条常用于生成 Molden 格式，第二条进入交互式网格输出。将数据交给 Multiwfn 后，再选择轨道、电子密度、静电势或键合分析；并非所有相关方法的密度都能由同一个通用转换路径完整表达。Chemcraft/Avogadro 适合查看结构和振动，图中应标清所用数据与方法。

## 续算与常见失败的处理

### 从旧轨道开始新的单点

```text
! PBE0 def2-SVP TightSCF MOREAD
%pal nprocs 4 end
%maxcore 2000
%moinp "water.gbw"
* xyzfile 0 1 water.xyz
```

新输入使用另一个前缀，避免覆盖要读取的旧文件。这个例子读取轨道作初猜，不恢复任意优化器或动力学状态。基组、电子数、自旋或方法变化时，应先核对读取与投影是否支持，再检查收敛到的电子态。[初猜参考](https://www.faccts.de/docs/orca/6.1/manual/contents/essentialelements/initialguess.html)给出了更多适用条件。

继续优化可从最后完整结构开始，必要时按任务复用 Hessian；这与从中断点无损恢复所有历史不同。遇到异常先保存输出和现有结构，再作单项修改，避免在同一目录反复覆盖而丢失故障线索。

| 现象 | 诊断步骤 |
| --- | --- |
| 输入解析失败 | 核对关键词所属模块、`end`、引号和坐标块终止 |
| SCF 不收敛 | 查结构、电荷、自旋、占据，再考虑初猜和收敛策略 |
| 优化很慢/振荡 | 查电子梯度噪声、软模和约束；必要时调整优化方式 |
| 内存或磁盘失败 | 比较每进程预算、总 RAM、scratch 容量和模块需求 |
| 并行模块无法启动 | 查完整程序路径、MPI 版本及环境，避免外层 `mpirun` |
| 有能量但无目标性质 | 查所选方法是否支持该性质以及对应模块是否完成 |

### 结果与任务状态

| 检查对象 | 重点 |
| --- | --- |
| `.out/.err`、PBS 输出 | 第一条实质错误、输入解析、模块名及内存/磁盘问题 |
| SCF/优化历史 | 电子收敛、结构阈值，而非仅出现了总能 |
| 频率/自旋与轨道 | 虚频、占据和自旋污染是否符合目标态 |
| 正常结束标记 | `ORCA TERMINATED NORMALLY` 只证明程序正常结束，不自动保证目标态正确 |

缺内存时先比较 `%maxcore × nprocs` 与总可用量，SCF 失败时先检查结构、电子数和自旋，再选合适算法。官方排错见[故障指南](https://www.faccts.de/docs/orca/6.1/manual/contents/quickstartguide/troubleshooting.html)。

## 第三方接口与资源

官方二进制包含大量内部数值模块，普通使用者通常无需自己编译积分库；外部 MPI 是并行运行的关键依赖。MRCC、DMRG 等扩展或外部程序接口需按对应功能单独配置，不能因主程序能启动就认为全部可用。

Multiwfn、Chemcraft、Avogadro、xTB/CREST 是常见辅助程序，各自的用途与许可不同。优先阅读与已安装版本匹配的[ORCA 手册](https://www.faccts.de/docs/orca/6.1/manual/index.html)；运行环境配置参见[本仓库安装笔记](ORCA安装.md)。
