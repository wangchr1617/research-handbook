# 分子动力学的 CUDA 计时与内存访问

比较 GPU 上的分子动力学实现时，先保持结构、势、精度、邻居策略、步长与输出频率一致，再区分内核时间和实际运行时间。小体系可能受启动和同步开销主导，大体系则可能受显存带宽、邻居表读取或力计算限制。

## 一、用同一个短跑量两种时间

用仓库的[两阶段短跑](GPUMD首个动力学与续算.md)搭一个对照。固定势、输入坐标和速度，再从同一状态计量 2,000 步 NVE。1 fs 步长对应 2 ps，若墙钟用时 0.5 s，吞吐就是 4 ps/s。这里的时间仅作换算示例。实际测量要记录 GPU、驱动、CUDA 工具链、编译架构、程序版本、原子数、平均邻居数和精度。

要定位力计算的开销，应在预热后于同一个 CUDA stream 内记录起止事件，同步结束事件，再读取 `cudaEventElapsedTime` 返回的毫秒数（见 [NVIDIA CUDA 计时说明](https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/index.html#timing)）；如果只在 CPU 侧包住异步 kernel launch，测到的主要只是任务提交开销。要判断实际模拟能快多少，则需另计包含必要同步、邻居表重建、数据传输和正常输出的墙钟时间。注意不要在每一步强制同步，以免打断流水执行，同步应放在测量区间边界。

## 二、看清邻居访问后再改数据布局

当 profiler 显示力内核受内存访问限制时，先区分连续读当前原子与按邻居索引间接读两种访问。把各坐标分量分别连续存放，有利于同一 warp 的线程合并读取当前原子的坐标。若邻居索引在内存中分散，访存仍可能产生多个事务。比较布局或分块时，同时看实际流量、内核时间和整段吞吐。

在成对相互作用的实现里，全邻居表可让每个线程只累加本原子的力，以重复遍历换取较少写冲突。半邻居表减少成对遍历，但更新同一对的两个原子时常需原子操作或归约。改用另一种布局后，先核对每步的能量和力，再判断吞吐变化是否值得。

先用小体系核对 CPU 和 GPU 的能量、力与压力，再比较稳定性和统计量。并行浮点归约可能让轨迹逐步分离，长期对照应使用相同条件下的分布和平均量。编译环境见 [GPUMD 编译指南](GPUMD编译.md)。

当前接口与调优说明见 [NVIDIA CUDA C++ Best Practices Guide](https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/index.html)。
