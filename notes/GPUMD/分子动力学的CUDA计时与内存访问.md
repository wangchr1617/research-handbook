# 分子动力学的 CUDA 计时与内存访问

比较 GPU 上的分子动力学实现时，先保持结构、势、精度、邻居策略、步长与输出频率一致，再区分内核时间和实际运行时间。小体系可能受启动和同步开销主导，大体系则可能受显存带宽、邻居表读取或力计算限制。

## 让计时能重现

1. 记录 GPU、驱动、CUDA 工具链、编译架构、程序版本、原子数、平均邻居数和浮点精度。预热后计时。用固定物理模拟时长比较吞吐，另做一次带正常输出的端到端测量。
2. 内核计时用同一 CUDA stream 的 events，读时间前同步结束事件。端到端计时需覆盖实际需要的数据传输、邻居表重建和输出。只在 CPU 上对异步 kernel 调用计时主要测到提交开销。
3. 用 profiler 区分内存与算力瓶颈。坐标和力按分量连续存储可帮助同一 warp 的线程合并访存，但邻居索引仍可能造成不连续读取。根据实际访问模式比较布局和分块。
4. 若采用“一线程处理一原子”的全邻居表，通常用额外计算换来少量跨线程写冲突。半邻居表减少对的遍历，但同时累加两端原子的力时需要原子操作或归约。比较时同时检查浮点累加顺序和实际数值误差。

先用小体系核对 CPU 和 GPU 的能量、力与压力，再比较稳定性和统计量。并行浮点归约可能让轨迹逐步分离，长期对照应使用相同条件下的分布和平均量。编译环境见 [GPUMD 编译指南](GPUMD编译.md)。

当前接口与调优说明见 [NVIDIA CUDA C++ Best Practices Guide](https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/index.html)。
