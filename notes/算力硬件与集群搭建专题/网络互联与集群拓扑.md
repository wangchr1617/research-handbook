# 为 MPI、存储与管理配置网络互联

适用环境：Linux 集群；拓扑规划通用。先根据通信量判断网络需求，再采购端口、网卡与线缆。

## 分清三类流量

| 网络 | 承担工作 | 起步设计 |
| --- | --- | --- |
| 带外管理网 | BMC/IPMI/Redfish、远程控制与硬件告警 | 独立管理 VLAN/交换网段，经 VPN 或管理入口访问 |
| 主机管理与服务网 | SSH、DNS、NTP、镜像部署、Slurm 控制 | 私网，登录入口受控，规划静态地址与名称解析 |
| 计算/存储数据网 | MPI 通信、NFS/并行文件系统、训练数据 | 按并发带宽和延迟预算配置，必要时计算与存储分网 |

物理分网提供独立带宽与故障域，VLAN 主要提供逻辑分隔，共享链路仍会争用。小集群可先合并部分主机流量，BMC 保持受限访问；扩容时根据实际拥塞拆分。

案例起步时，两个计算节点与存储服务器接同一数据交换机，另接管理网。无论选什么速率，都画出“节点端口 → 线缆 → 交换机端口 → 存储/上联”的端口表，把未来节点与备用端口算进去。

## 以太网、InfiniBand 与 RoCE 怎么选

| 方案 | 更适合的前提 | 需要承担的工作 |
| --- | --- | --- |
| 普通以太网 TCP/IP | 独立作业、适中的共享存储流量 | 低延迟需求不高时部署简单；高速率不保证 MPI 延迟低 |
| InfiniBand | 跨节点 MPI/训练通信重要，应用与 MPI 有成熟支持 | HCA、IB 交换机、线缆、Subnet Manager 和 RDMA 软件栈 |
| RoCE 以太网 RDMA | 希望复用以太网，同时具备 RDMA 网络设计能力 | 端到端核对网卡、交换机、路由、拥塞控制及 PFC/ECN 策略 |

RoCE 的具体无损/拥塞策略取决于实现与厂商方案，不能把“插上高速以太网线”当成配置完成。InfiniBand 链路变成 Active 还需要正确的子网管理；IB 与以太网即使使用相似外观的连接器，也不能据此互插通信。双协议卡还需核对端口工作模式和固件。

理论上 `100 Gb/s ÷ 8 = 12.5 GB/s`，协议、编码、包大小与软件开销使有效应用吞吐更低。小消息通信看延迟，大消息看带宽，Allreduce/Alltoall 还受拓扑与进程布局影响。双口网卡不代表单连接速度翻倍，LACP 也通常不能让单个流自动吃满两条链路。

## 交换机与线缆如何算完整

假设 4 个节点各用 100 Gb/s 连到一台接入交换机，上联存储仅 100 Gb/s，则四节点共享上联，名义超售为 4:1。各节点彼此通信是否也受上联影响，要看目的节点位置和交换结构。比较交换容量、每端口速率、上联、缓冲、管理与支持，而不仅看端口数量。

DAC 适合较短机柜内连接；AOC/光模块适合更远距离，但需核对距离、模块功耗和厂商兼容列表。将模块、跳线、网卡、交换机和许可/维保作为同一套报价。PCIe 槽位带宽不足、网卡在另一 CPU 下、劣质线缆都会使采购的标称速率落空。

小节点数可评估直连，但要计算端口数、IP/路由、故障路径与增长方式；两节点直连成功不能代表后续多节点网络已设计好。大规模再评估叶脊/Fat-tree 和双向带宽，起步集群无需为未知规模预购复杂拓扑。

## 按层验收链路

Linux 节点可查看：

```bash
ip -br addr
ip route
ethtool enp1s0
rdma link
ibv_devinfo
```

`enp1s0` 替换为实际网卡；后两条需要 RDMA 工具包和设备。检查协商速率、双工、MTU、路由、RDMA 端口状态、计数器和交换机对应端口。Jumbo MTU 要端到端一致；不能只改节点一侧。

1. 先测管理网解析、时钟与 TCP 连通，再用 iperf3 在受控测试窗口测吞吐；记录单流/多流、双向与并发结果。
2. RDMA 方案用厂商 perftest 工具验证数据路径，再运行 OSU Micro-Benchmarks 或 Intel MPI Benchmarks；记录 MPI、UCX/libfabric 版本和消息大小。
3. 用目标应用测 1、2 节点强扩展，再加入多个同时作业和存储流量，检查退化与错误计数。
4. 若 TCP 正常而 MPI 卡住，依次检查 MPI/PMI 匹配、选用的传输层、路由/防火墙、MTU 与 RDMA 设备。根据日志证明实际走 RDMA，避免静默回退 TCP 后误判成功。

GPU 跨节点通信还需验证 NCCL/RCCL 与 GPU—网卡拓扑；GPUDirect RDMA 要平台、驱动和软件一起支持，普通 RDMA 测试通过不代表 GPU 直通已经启用。

参考 [NVIDIA 网络文档入口](https://docs.nvidia.com/networking/)、[RoCE 配置示例](https://enterprise-support.nvidia.com/s/article/recommended-network-configuration-examples-for-roce-deployment)、[UCX 文档](https://openucx.readthedocs.io/en/master/)和[Slurm MPI 指南](https://slurm.schedmd.com/mpi_guide.html)。具体交换机与固件配置采用相同版本的厂商指南，网络验证与[部署](从裸机到Slurm集群.md)、[应用验收](验收监控与故障处理.md)连起来做。
