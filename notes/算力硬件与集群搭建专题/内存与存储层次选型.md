# 配置内存、系统盘、临时盘与共享数据存储

适用环境：选配通用；检查命令面向 Linux。目标是让计算装得下、数据供得上、重要结果能恢复。

## 先区分每一层在做什么

| 层次 | 放什么 | 关键指标与代价 |
| --- | --- | --- |
| CPU 缓存 | 由硬件管理的热点数据 | 低延迟、容量小，工作集与访问模式影响命中率 |
| GPU 显存 | GPU 模型、波函数、工作区 | 容量与带宽决定可处理规模；主存不能无代价替代 |
| ECC 主存 | 活跃进程数据、文件缓存 | 容量、通道带宽、NUMA 本地性和纠错能力 |
| 本地 NVMe scratch | 可重建的临时文件、检查点暂存 | 延迟、持续写入、耐久度、散热与掉电保护 |
| 共享项目盘 | 输入、软件、协作数据与结果 | 多用户吞吐、元数据、权限、容量和可用性 |
| 备份/归档 | 重要数据的独立副本或长期保存 | 恢复时间、保留期、介质寿命与异地成本 |

节点 A 的内存不能自动借给节点 B。MPI 程序需自己分布数据，一些步骤还会复制数据；共享文件系统只让文件可见，不能把两台机器变成一块共享内存。

## 内存容量与通道一起算

案例中若一个作业实测每节点峰值 60 GiB，要并发两份作业，再加 OS、文件缓存和增长余量，先估约 160 GiB 以上，再选平台支持的容量与插法。例如 12 通道单路平台可比较 `12 × 16 GiB = 192 GiB` 与 `12 × 32 GiB = 384 GiB`；8 通道平台可比较 `8 × 32 GiB = 256 GiB`。这些是教学组合，必须核对整机支持的 DIMM 型号和容量。

理论数据带宽可按 `通道数 × 数据率 × 8 字节` 估算。例如 12 通道 DDR5-4800 为 460.8 GB/s，8 通道为 307.2 GB/s；这是十进制理论数据带宽，不是应用实测，也不额外乘 ECC 位宽或再次乘“双倍”。数据率单位为 MT/s，不能直接写成实际时钟 MHz。

按主板手册的优先槽位插条，每通道 1 条称 1DPC。增加到 2DPC 可能降频；CPU、主板和 DIMM rank 都会影响结果。RDIMM 与 UDIMM、不同 DDR 代际不能混用；DDR5 的片内 on-die ECC 不等于整机支持端到端 ECC。扩容前记录已有条的料号、rank、速度与实际运行频率，避免只按容量购买。

Linux 管理员可检查：

```bash
free -h
sudo dmidecode --type memory
numactl --hardware
```

`free` 的 `available` 比仅看 `free` 更适合判断当前可供作业使用的内存；固件报告与 OS 可用容量可能有差别。DIMM 配置检查与实际带宽测试要分别进行。

## 磁盘怎样分工

系统盘存 OS 与配置，可按可用性要求选镜像；镜像便于单盘故障后继续运行，配置仍需另行备份。计算节点另设 NVMe 临时盘，登录与共享服务避免和高强度 scratch 抢同一块盘。

SSD 比较接口、容量、持续吞吐、随机 IOPS、DWPD/TBW、掉电保护与保修条件。教学演算：每天写 4 TB、容量 2 TB，相当于 2 DWPD 的工作负载；再与厂商额定使用年限和工作负载定义比较。缓存耗尽后的速度、写入放大和剩余空闲空间会影响长任务；桌面盘短时间的峰值不能替代持续写入验收。

SATA、SAS 与 NVMe 描述不同链路协议；M.2、U.2 等主要描述形态或连接方式。相同尺寸或接口外观不保证背板支持所需协议。检查背板、线缆、HBA/RAID 卡、PCIe 分叉和热插拔能力。HDD 适合容量存储时，要进一步核对 CMR/SMR 及重建工作负载，避免把不适配的盘放入阵列。

## NFS、并行文件系统与备份

两三个节点、独立任务为主时，可从独立 NFS 服务起步；用实际并发验证服务端内存、网卡、磁盘与元数据能力。大量小文件会先耗尽 inode 或让目录操作拥塞，顺序 GB/s 高也不能保证训练数据加载快。多节点持续高并发 I/O 时再比较 Lustre、BeeGFS 等并行文件系统，并计入元数据服务、网络与运维成本。

RAID10 通常牺牲约一半原始容量换取镜像和条带；双校验阵列的名义容量约为 `(N−2) × 单盘容量`，还需扣除热备、文件系统、快照和保留空间。实际可用性受故障组合、重建时间与控制器影响。

RAID 不能恢复误删、勒索或机房事故；快照若和源盘同故障域，也不能充当独立备份。

按数据价值设 RPO（可接受丢失多久的数据）和 RTO（多久恢复服务）。例如项目结果每天备份、每月抽样恢复一次，原始不可重建数据另存异地副本；备份频率由课题实际需求决定。保存权限、UID/GID、校验和与恢复步骤，恢复演练应在临时目录完成。

容量预算还需区分原始容量、阵列可用容量和实际业务余量。例如每周保留 0.5 TB 新数据、保存一年，净新增约 26 TB；再加入现有数据、快照与增长余量，独立备份另算。若采用 8 块 8 TB 盘的双校验阵列，名义容量为 48 TB，格式化后显示的 TiB 更小，且还未扣除热备和运行余量。不要把厂商 TB 与 OS 显示的 TiB 差异误判为丢盘。

## 作业怎样使用临时盘

为每个作业建立唯一 scratch 目录，先复制输入，运行结束后把结果和必要检查点复制回项目盘，并校验成功，再由策略清理临时文件。失败作业保留日志和可用检查点；不能在无条件退出钩子中删除唯一结果。管理员公布 scratch 配额和清理期限，用户定期检查：

```bash
df -h
df -i
findmnt
```

`df -h` 看容量，`df -i` 看 inode，`findmnt` 确认路径实际挂载到哪里。共享挂载失败后若目录仍存在，作业可能把数据写进系统盘；部署时增加挂载依赖和健康检查。NFS 配置按内网、最小权限和 `root_squash` 设计，不能为了写入方便对所有客户端开放 root 权限。

平台内存限制见 [AMD 9004 数据表](https://www.amd.com/content/dam/amd/en/documents/epyc-technical-docs/data-sheets/221700653-C_en_AMD-EPYC-9004-Series-Processors---Data-Sheet_pdf.pdf)与 [Intel 6448Y 内存规格](https://www.intel.com/content/www/us/en/products/sku/232384/intel-xeon-gold-6448y-processor-60m-cache-2-10-ghz/specifications.html)；NFS 管理可查所用发行版的 `exports(5)`、`nfs(5)` 手册，具体盘和背板以整机支持列表为准。
