# 按软件、精度与显存选择 GPU、MaPU 等加速器

适用环境：选配通用；驱动与计算环境面向 Linux。资料核对日期：2026-11-07。

加速卡的价值取决于程序能否把主要耗时工作交给它。先确认软件的具体版本、加速后端和支持功能，再借用目标平台运行代表输入。VASP、CP2K、分子动力学和机器学习对精度、显存和通信的要求不同，“AI 算力高”不能直接推出电子结构计算快。

## 怎样阅读 GPU 规格

| 参数 | 选型时要问什么 | 常见错误 |
| --- | --- | --- |
| 显存容量 | 实际问题、batch、优化器、激活与工作区是否能装下 | 把两张卡显存相加当作单卡连续内存 |
| 显存带宽 | 内核是否受搬运数据限制 | 只看容量，忽略 GDDR/HBM 带宽 |
| FP64/FP32/BF16 等 | 应用关键步骤用什么精度，误差是否合格 | 拿稀疏低精度 Tensor 峰值比较 FP64 |
| 普通计算与矩阵单元 | 程序是否调用对应矩阵路径 | 把 Tensor FP64 等同于全部 FP64 内核 |
| 互联与 PCIe | 设备间通信走何种链路，拓扑怎样 | 认为同品牌多卡自然有 NVLink |
| ECC、功率、形态 | 长作业可靠性，供电和风道是否匹配 | 将被动散热卡放进无强制风道的机箱 |

## 代表型号怎样用于比较

| 代表型号/形态 | 适合列入比较的任务 | 采购时必须分清 |
| --- | --- | --- |
| NVIDIA A100 40/80 GB | 已有 CUDA 后端的科学计算与训练 | PCIe/SXM、容量、板卡功率与互联不同 |
| NVIDIA H100 | 高端训练、支持其后端的 FP64 计算 | PCIe、SXM、NVL 规格分别核对，整机形态不同 |
| NVIDIA L40S 48 GB | 支持 CUDA 的训练、推理与图形任务 | 主要定位 AI/图形，FP64 密集任务必须试算，不能套 H100 性能 |
| AMD Instinct MI300X 192 GB HBM3 | 支持 ROCm/HIP 的大显存训练、推理与科学程序 | OAM 平台与整机互联，软件移植和版本支持 |
| 桌面 GeForce/工作站卡 | 开发、小规模训练和可视化的候选 | 显存、ECC、持续功率、尺寸、许可和服务条款逐项核对 |

型号信息见 [A100](https://www.nvidia.com/en-eu/data-center/a100/)、[H100 数据表](https://resources.nvidia.com/en-us-gpu-resources/h100-datasheet-24306?xs=443990)、[L40S](https://www.nvidia.com/en-us/data-center/l40s/)与 [MI300X](https://www.amd.com/en/products/accelerators/instinct/mi300/mi300x.html)官方页。卡型、供应地区和可获得的保修服务也应写进采购清单。

优先测试一个任务能否放进单卡，再决定多卡。数据并行通常在各卡保留模型副本；只有张量/流水线并行、分片等显式机制才会改变每卡存储。CPU 内存卸载会增加主存和 PCIe 传输需求。主存容量不能机械地按显存的固定倍数购买，应量测数据预处理、缓存和并发占用。

## 软件兼容性先做小规模证明

NVIDIA 方案核对 GPU 架构、宿主驱动、CUDA 运行时、编译工具链与应用二进制。`nvidia-smi` 显示的 CUDA 版本是驱动支持能力的提示，不证明相同版本 Toolkit 已安装。驱动与运行时配合遵循 [CUDA 兼容性说明](https://docs.nvidia.com/deploy/cuda-compatibility/)。

AMD GPU 方案按 [ROCm 兼容矩阵](https://rocm.docs.amd.com/en/latest/compatibility/compatibility-matrix.html)逐项核对 GPU、OS、内核与框架。AMD CPU 可以搭 NVIDIA GPU，Intel CPU 也可以搭 AMD GPU；CPU 品牌与加速后端不是绑定关系。程序只有 CUDA 实现时，换成 ROCm 可能需要代码和依赖移植。

到候选机器上运行与最终相同精度、规模和功能的输入，记录输出误差、峰值显存、吞吐、GPU 利用率、功率和设备间传输。容器只封装部分用户态依赖，不能补足不兼容的宿主驱动、指令集或硬件能力。多用户通过 Slurm 分配 GPU，并检验设备限制，见[部署笔记](从裸机到Slurm集群.md)。

## MaPU、NPU、FPGA 应怎样评估

MaPU 缩写需要落到厂商、完整产品和编程模型。中科院自动化所的[国家专用集成电路设计工程技术研究中心介绍](https://www.ia.cas.cn/jgsz/kyxt/bm4/)使用 Mathematics Process Unit（代数运算微处理器）这一名称，介绍的是早期 AppAISArc 架构及研制计划。该资料可说明术语来源，无法据此确定今天的供货型号、Linux 驱动或 VASP/CP2K 支持。

对以 MaPU 名称销售的平台，先索取以下证明，再纳入正式采购对比：

1. 完整芯片/板卡/整机型号、可交付数量、保修和生命周期。
2. SDK、编译器、数学库、调试器、OS 与内核支持矩阵，离线安装与升级方式。
3. 原程序能否重编译、哪些算子需移植、FP64 或混合精度的实际能力。
4. 用自己的输入测得的正确性、端到端耗时、显存/片上存储与主机传输开销。
5. 多卡通信、调度接入、监控接口和故障恢复，以及移植人员的持续投入。

如果公开资料不足，采购表标为“待供应商验证”，不把早期峰值算力折算成可交付应用性能。NPU/TPU 常针对特定张量与精度路径，FPGA 需要开发或采用成熟硬件内核；它们也遵循同样的验收方法。已有稳定专用流水线、持续任务量和维护团队时，再比较其吞吐与能耗收益。

## 多卡整机下单前

让供应商提供 GPU—CPU—网卡—NVMe 的 PCIe/NUMA 拓扑图、插槽电气带宽和整机最大配置功率。检查 GPU 长度、厚度、重量、供电接口、线缆弯折空间、风道和转接卡。SXM/OAM 模块需要相应服务器平台，不能作为普通 PCIe 卡自行插入桌面主板。

若任务会跨节点同步梯度或矩阵，先检查节点内互联，再按[网络笔记](网络互联与集群拓扑.md)测试跨节点通信；低利用率也可能来自数据盘和 CPU 喂数不足，不能一概通过加卡解决。
