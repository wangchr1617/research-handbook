# 从计算任务推导集群配置与预算

适用环境：通用；测量命令在 Linux 的已分配计算资源中执行。

采购前先回答两个问题：单个任务要多少资源，团队同时会运行多少任务。把“想买多少核”改成“每周需要完成多少个指定规模的计算”，才能比较高主频 CPU、大内存节点、GPU 与外购算力。

## 先做负载画像

从最近的作业中选小、中、大三个真实输入，固定软件版本、编译选项和数值收敛标准。记录下表；没有历史任务时，先租用或借用候选机器试算。

| 项目 | 需要记录的内容 | 对选型的影响 |
| --- | --- | --- |
| 软件与许可 | 版本、CPU/GPU 后端、按核或节点收费、容器与云端运行条款 | 决定可用架构与长期费用 |
| 问题规模 | 原子数、基组、k 点、网格；或模型、精度、batch size | 定义对比输入，避免小样本误导 |
| 单任务资源 | 实际耗时、峰值内存、显存、读写量和临时空间 | 给出节点最低能力 |
| 并行扩展 | 同一输入 8/16/32/64 核与 1/2 节点耗时 | 判断增加核心还是增加独立节点 |
| 并发与时限 | 每日任务数、同时活跃人数、最长可接受周转时间 | 确定节点数量与排队策略 |
| 数据与机房 | 年增量、保留期、备份恢复时间、供电与散热上限 | 决定存储和部署位置 |

例如对 CP2K 分别测 16、32、64 个物理核，保持 MPI/OpenMP 布局可追溯。在线程数已固定时，用 `/usr/bin/time -v` 包围实际启动命令，查看 `Elapsed`、退出码和 `Maximum resident set size`。这个内存值不能直接当作分布式作业全节点内存总和：同时读取调度器记录、每节点内存监控和应用日志。Slurm 的 `MaxRSS` 还取决于采集插件与作业步，见[验收笔记](验收监控与故障处理.md)。

定义强扩展加速比与效率：

$$
S(p)=T(p_0)/T(p),\qquad E(p)=S(p)/(p/p_0).
$$

这里固定问题规模，`p0` 是基准核心数。教学示例：16 核 100 分钟、32 核 60 分钟，则加速比为 1.67、效率为 83.3%；这组数是演算数据。

若 64 核降到 55 分钟，每任务核心分钟从 1920 增至 3520，团队吞吐优先时可以把两份任务各放 32 核。真实决策还需比较排队时间、内存和软件授权。

## 起步集群怎样分工

案例中的 6 人团队先用 2 个 CPU 计算节点，每节点按试算选择 32～64 个物理核、192～384 GiB 内存，配本地 NVMe 临时盘。这个范围是教学容量预算，具体条数必须按[内存通道](内存与存储层次选型.md)调整。独立任务占主导时先配置可靠的以太网；只有跨节点 MPI 试算显示通信成为主要成本，才比较 RDMA 方案。

管理/登录服务可在起步阶段合并到一台独立小服务器，计算节点专门执行作业。共享存储可从独立存储服务器的 NFS 开始，同时部署另一份离机备份。合并登录与管理会扩大单点故障影响，增长后再拆分。GPU 节点在确认目标软件后加入独立分区，避免为尚未验证的加速需求提前占用预算。

| 需求 | 优先投入 | 需要先确认的代价 |
| --- | --- | --- |
| 大量独立小任务 | 多个容量均衡的 CPU 节点 | 管理数量、许可证、共享盘小文件压力 |
| 单个任务经常内存不足 | 大内存节点、足够内存通道 | 大容量 DIMM 价格、带宽与扩容插法 |
| 单任务需跨节点强扩展 | 低延迟互联与均衡节点 | 交换机、线缆、网卡与 MPI 运维 |
| GPU 已有明确实测加速 | 对应后端的 GPU 整机 | 显存、CPU 喂数、驱动、功率与保修 |
| 需求不稳定或使用率低 | 公共平台或按量算力 | 数据搬运、配额、出口流量、许可与保密要求 |

## 用采购清单比较整机

每家供应商按相同条件报价，要求写明替代件是否允许、含税运费、交付期、保修范围与验收失败处理。CPU 报价不能代替完整节点报价。

| 清单项 | 应写到的粒度 |
| --- | --- |
| 计算节点 | CPU 完整 SKU 与数量，主板型号/修订版、BIOS，内存条型号/条数/插法 |
| 扩展设备 | GPU 具体形态与显存、网卡端口/速率、转接卡、PCIe 分配图 |
| 存储 | 系统盘与数据盘数量、容量、耐久度、背板协议、RAID/HBA 模式 |
| 机箱与机房 | 机架高度/深度、导轨、重量、风扇、冗余电源、输入电压与接头 |
| 网络 | 管理/计算/存储交换机、可用端口、上联、DAC/AOC/光模块、支持服务 |
| 软件与交付 | OS、驱动/MPI/调度器版本、授权、可复现安装记录、应用验收输入 |
| 运维 | 备件、保修响应、机房费用、备份介质、管理员工时 |

三年总成本可按 `整机与网络 + 软件许可 + 电费与制冷 + 机柜与维保 + 备份 + 管理工时` 估算。

电费示例：IT 平均功率 2 kW、全年运行、机房 PUE 假设为 1.5、电价假设为 0.8 元/kWh，则年费用为 `2 × 8760 × 1.5 × 0.8 = 21024 元`。这些是假设值，报价时替换为合同电价和机房实测；若机房已按含制冷费用计价，不重复乘 PUE。

把应用吞吐量除以三年总成本，结合单任务时限比较。预算紧时先保住内存、数据保护和可维护性，减少未经证实有收益的核心或加速卡。预留交换机端口、机柜功率、空盘位与网卡槽位，比只预留 CPU 插槽更有用；有些单路主板和 P 系列 CPU 从一开始就无法扩成双路。

## 采购前形成可检查的结论

提交一页决策记录：三类代表任务、候选配置的耗时/内存/功耗、并行布局、预计并发、含税清单、机房条件、备份与运维责任人，以及未通过验证的兼容项。验收条款写应用完成时间、结果误差、同时作业数、恢复要求，具体阈值来自试算与合同。
