# 高性能计算软件编译常识

**适用环境：Linux HPC；macOS 本机编译需采用对应工具链，生成的程序不能直接复制到 Linux 运行。**

以 CP2K、LAMMPS、VASP 为例，安装失败常常不是“少敲了一条命令”，而是编译器、MPI、数学库或目标架构没有配套。先理解构建链条，再照软件自己的版本文档操作。

## 开始前

先拿到软件的授权源码、目标计算环境和可用工具链，不必先自行安装全部编译器。Linux 集群先请管理员确认编译节点、Module 名称和编译作业的资源申请方式；没有系统权限时在个人目录安装。

| 要准备什么 | 官方入口或获取方式 |
| --- | --- |
| CMake | [下载与安装](https://cmake.org/download/)，核对项目要求的版本 |
| GNU 编译器 | [GCC 官方安装说明](https://gcc.gnu.org/install/)，集群优先使用现成 Module |
| MPI | [Open MPI](https://www.open-mpi.org/software/)，必须与目标软件和集群运行环境配套 |
| CP2K 源码 | [CP2K 下载说明](https://www.cp2k.org/download)，按版本文档准备依赖 |
| LAMMPS 源码 | [LAMMPS 下载页](https://www.lammps.org/download.html) |
| VASP 源码 | [VASP 官方入口](https://www.vasp.at/)，向课题组确认许可与授权下载方式 |

Mac 本机先按 [新生入门](新生入门（Mac）.md#二安装常用工具)安装命令行工具和 Homebrew。若项目需要 GNU Fortran，可用 `brew install gcc cmake` 准备，再查看实际编译器命令；Mac 上的 `gcc` 也可能仍指向 Apple Clang，后续以版本输出为准。

## 一、先判断是否需要编译

先看 [Module](Module使用.md) 中是否已有可用版本，软件功能、精度和并行方式是否符合任务要求。有官方二进制或 Conda 包时，也可以先用它跑通小例子。

确实需要新功能、专用硬件支持或源码修改时，再准备编译。VASP 等软件须先获得授权源码；不要下载来源不明的可执行文件。

## 二、编译的几个阶段

| 阶段 | 做什么 | 常见问题 |
| --- | --- | --- |
| 配置 | 检测依赖、生成构建规则 | 找不到头文件、库或编译器 |
| 编译 | 源码生成目标文件 | 语法、编译器版本、内存不足 |
| 链接 | 将目标文件与库组成程序 | `undefined reference`、库顺序或 ABI 不匹配 |
| 安装 | 将程序、库和数据放入目标目录 | 前缀或权限不合适 |
| 运行验证 | 在目标节点执行测试 | 动态库缺失、指令集、MPI 启动问题 |

“配置成功”只代表生成了构建文件，不等于软件已经编译完成；“生成可执行文件”也不等于能在计算节点正确运行。

## 三、先记录工具链

在允许的编译节点或 PBS 交互作业中检查：

```bash
uname -m
module list
command -v gcc gfortran mpicc mpifort cmake
gcc --version
gfortran --version
mpicc -show
mpifort -show
cmake --version
```

`-show` 适用于部分 MPI，OpenMPI 可按其帮助用 `--showme`。MPI 包装器会调用底层编译器并附加参数；它不是独立于编译器的另一种语言。

C / C++ / Fortran 编译器尽量来自同一套工具链。用 Intel MPI 编译的软件不要随意换成 OpenMPI 运行；Fortran 的 `.mod` 文件尤其依赖编译器和版本。

## 四、常见依赖

- **BLAS / LAPACK**：线性代数基础库，常见实现有 OpenBLAS、MKL。
- **ScaLAPACK**：分布式线性代数，通常还需要 MPI。
- **FFTW**：傅里叶变换，注意精度、线程和 MPI 变体。
- **OpenMP**：进程内线程并行；MPI 则用于进程间通信。
- **CUDA / GPU 库**：同时受 GPU 型号、驱动和工具包版本约束。

LP64 与 ILP64 涉及整数接口宽度；库文件存在并不代表接口匹配。头文件、链接库和运行时库应来自同一安装。

## 五、分开源码、构建和安装目录

个人软件可以组织为：

```text
~/Software/
├── src/myapp-1.0/
├── build/myapp-1.0-gcc-mpi/
└── apps/myapp/1.0-gcc-mpi/
```

不要在系统目录安装个人软件。不同版本、编译器或 MPI 使用不同构建目录和安装前缀，便于回退。

以支持 CMake 的项目为例，下面路径和编译器需要替换：

```bash
cmake -S "$HOME/Software/src/myapp-1.0" \
  -B "$HOME/Software/build/myapp-1.0-gcc-mpi" \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_INSTALL_PREFIX="$HOME/Software/apps/myapp/1.0-gcc-mpi"
cmake --build "$HOME/Software/build/myapp-1.0-gcc-mpi" --parallel 4
ctest --test-dir "$HOME/Software/build/myapp-1.0-gcc-mpi" --output-on-failure
cmake --install "$HOME/Software/build/myapp-1.0-gcc-mpi"
```

并行度按实际申请的核数和内存设置；这不是提交到调度器的命令，需要在已获准的资源中运行。项目未注册 CTest 时，必须另跑软件提供的测试，不能把“没有找到测试”当作通过。

MPI 项目可能需要显式指定 `CMAKE_C_COMPILER=mpicc`、`CMAKE_Fortran_COMPILER=mpifort`，也可能由项目自行查找 MPI，按软件文档选择。Autotools 项目常使用 `./configure --prefix=... && make && make install`，并非所有软件都支持 CMake。

换编译器或依赖后，新建构建目录重新配置，避免旧缓存继续引用原路径。构建工具概念见 [CMake 官方教程](https://cmake.org/cmake/help/latest/guide/tutorial/index.html)。

## 六、运行检查与性能

Linux 可用 `ldd /path/to/program` 检查动态库，macOS 对应 `otool -L /path/to/program`。只对来源可信的程序检查。

接着通过 [PBS](PBS作业管理系统使用.md)跑软件的小型官方测试：先串行或少量进程，再测试 MPI / OpenMP，比较参考能量、力、单位和允许误差。增加核数后还要比较耗时；能够启动不代表并行效率好。

以 GeTe 为例，固定同一结构、输入和收敛阈值，再比较不同构建的能量与力。不能把输入变化造成的差异归因于编译器优化。

`-march=native` 会针对编译所在 CPU 优化；异构集群中，程序可能在旧节点报 `Illegal instruction`。GPU 构建同样需要明确目标架构。长任务运行前先在实际目标节点试跑。

## 七、按错误阶段排查

| 报错 | 排查方向 |
| --- | --- |
| `No such file` / 找不到头文件 | 依赖安装、include 路径、配置缓存 |
| `undefined reference` | 缺少链接库、接口版本、静态库顺序 |
| `error while loading shared libraries` | 运行节点动态库路径、RPATH、Module 环境 |
| 编译中 `Killed` | 内存或配额限制，检查日志并降低并行度 |
| MPI 启动失败 | 启动器、软件和 MPI 的版本是否配套 |
| 程序崩溃或数值异常 | 官方测试、输入、线程与库接口，不先盲目加优化 |

保留源码版本、构建命令、模块列表、关键日志和测试结果。具体软件见 [CP2K 编译](../notes/cp2k/CP2K编译与部署.md)、[LAMMPS 安装](../notes/lammps/LAMMPS安装.md)、[VASP 编译](../notes/vasp/VASP编译.md)。
