# Codex 配置与使用技巧

**适用环境：macOS / Linux 本机终端，以及 ChatGPT 桌面应用中的 Codex；侧聊、侧边栏和 dot 按对应界面使用。**

Codex 可以读取项目、修改文件和运行命令。先让它理解项目约定，再给一个能检查结果的小任务，比直接要求“把所有问题修好”更容易得到可靠结果。

## 开始前

先准备可用邮箱和网络，再从 [ChatGPT](https://chatgpt.com/)注册或登录账号；支持哪些登录和计费方式，按 [官方快速开始](https://developers.openai.com/codex/quickstart/)与登录页面确认。ChatGPT 订阅和 API 余额分别管理，不需要为了开始尝试同时购买两者。

Mac 用户按 `Cmd+空格` 搜索“终端”；Linux 用户打开本机终端。先创建一个没有重要数据的练习目录：

```bash
mkdir -p "$HOME/projects/codex-demo"
cd "$HOME/projects/codex-demo"
```

若后面要用 `git status` / `git diff`，Mac 先按 [新生入门](新生入门（Mac）.md#二安装常用工具)安装 Git，Linux 使用发行版或管理员提供的 Git；普通文件夹尚未初始化 Git 时，先执行 `git init`。

## 一、安装和登录

桌面应用从 [Codex 官方入口](https://developers.openai.com/codex/app/)下载。命令行安装见 [官方 CLI 文档](https://developers.openai.com/codex/cli/)，macOS / Linux 也可先下载官方安装脚本检查：

```bash
curl -fsSL https://chatgpt.com/codex/install.sh -o /tmp/codex-install.sh
less /tmp/codex-install.sh
sh /tmp/codex-install.sh
codex --version
codex --help
```

按安装器提示配置 PATH，重新打开终端，进入上面的练习目录运行 `codex`。选择 ChatGPT 登录时，打开提示的浏览器页面并完成授权；选择 API Key 时，从 [OpenAI API 平台](https://platform.openai.com/)创建 Key 并按提示设置，API 路线需要单独确认计费与余额。

启动后先输入“请列出当前工作目录，暂时不要修改文件”，检查返回目录，再继续编辑任务。密钥不写进仓库。

桌面应用选择已有项目目录；CLI 则从要操作的目录启动。先用 `pwd` 和 `git status --short` 确认位置与已有改动。

## 二、把约定写在 AGENTS.md

在项目根目录用 VSCode 或纯文本编辑器新建 `AGENTS.md`（已有文件就补充原文件），写入项目共同约定，例如：

```markdown
# 项目约定

- 用中文解释结果，笔记开头标注适用环境。
- 输入模板放 inputs，专题笔记放 notes。
- 修改前保留已有未提交内容，不覆盖计算原始数据。
- 科学计算先用小体系验证，报告单位、条件和验证范围。
```

约定写清行为和结果判据，不需要堆积大量泛泛的提示词。子目录可以补充更具体的规则；让 Codex 开工前读取适用的项目约定。

## 三、配置与权限

用户级配置通常在 `~/.codex/config.toml`；项目也可有 `.codex/config.toml`，项目配置是否加载受信任状态和组织策略影响。配置层级见 [官方配置说明](https://developers.openai.com/codex/config-basic/)。

本机 CLI 常用的配置示例：

```toml
approval_policy = "on-request"
sandbox_mode = "workspace-write"
```

第一次配置时，在终端执行 `mkdir -p "$HOME/.codex"`，再用纯文本编辑器打开或新建该目录中的 `config.toml`，粘贴需要的配置并保存；不要保存为 `config.toml.txt`。只合并需要的键，不整文件覆盖已有配置。工作区写入权限、外网访问权限和远端账号权限是不同层面；组织管理环境还可能限制可用选项。不要把关闭全部审批当作安装后的必做步骤。

模型从当前界面或帮助中选择可用项；长期笔记不固定“最新模型”的名字。报错时先记录 `codex --version`、运行目录和完整错误，再查对应版本说明。

## 四、把任务说具体

以处理 GeTe 的能量数据为例：

```text
请读取 scripts 和 examples 中已有的能量处理流程。
新增一个脚本，从我提供的两列体积、能量数据绘图，单位分别为 Å³ 和 eV。
保留原始数据，沿用项目风格，给出运行命令并用小数据检查结果。
最后说明修改了哪些文件、验证了什么，以及还需要我判断的地方。
```

任务中说明输入、目标、限制和判据，允许助手读取相关文件；处理中可继续补充条件。结束后结合 diff 与实际产物检查结果。

```bash
git diff --stat
git diff --check
git diff
```

新文件还要通过 `git status --short` 和编辑器查看，默认 `git diff` 不显示未跟踪文件的内容。Git 管理见 [Git 入门](git/Git入门.md)。

### 材料计算任务怎样核对

让 AI 辅助准备 VASP 或 CP2K 输入时，同时给出所用版本、目标性质、模型与相应手册章节。要求它说明每个新增设置的用途和依据，再核对周期性、电子数与自旋、基组或赝势、采样和精度。程序接受关键词，只说明通过了输入解析；正式批量运行前，仍需用小模型检查目标电子态、收敛和物理量。

处理已有输出时，要求保留原文件，并为每个汇总量标出文件、输出段落、单位和能量参考。抽取一个结构手工核对，再检查脚本对中断任务、缺失值及多阶段输出的处理；没有结果的条目保留原因，不补成零或由 AI 估算。阅读文献时也回到原文检查方法与限制，引用要核对论文是否支持当前说法；DOI 可访问、多个模型回答一致，都不能替代独立证据。

## 五、集群、技能与 MCP

集群操作采用[本机 Codex → SSH → PBS](Codex连接科研集群（macOS）.md)，先验证只读查询，再提交明确资源的任务。工具调用成功和计算正确是两件事，仍需检查程序日志与物理结果。

Skills 提供工作流程，MCP 接入工具和数据源，安装示例见 [技能与 MCP 工具](技能与MCP工具的安装及使用技巧.md)。一次只加当前任务需要的能力，并用小任务验证是否实际可用。

## 六、常见问题

| 现象 | 检查方向 |
| --- | --- |
| 终端找不到 `codex` | PATH、安装位置、是否重新打开终端 |
| 命令能执行但无法联网 | 当前会话网络策略、应用代理和 [DOVE](DOVE加速器配置与使用技巧.md) |
| 一直要求重复确认 | 权限策略、可写目录是否包含实际项目位置 |
| 没有遵循项目约定 | 启动目录、适用的 AGENTS.md、任务是否明确要求读取 |
| 报告完成但结果缺失 | 文件是否实际生成、命令退出状态、测试及输出是否检查 |

具体命令以已安装版本的 `--help` 为准。

## 七、用 /goal 持续完成一个目标

需要经过多轮检查、修改和验证的任务，可以用 `/goal` 写清结果、边界和完成条件。例如在 Codex 输入框发送：

```text
/goal 为 GeTe 的能量—体积数据建立可复用的分析流程：
读取 data 中的两列数据，单位分别为 Å³ 和 eV，输出带单位的曲线及最低能量对应的体积。
保留原始数据和已有修改，附运行方法，并用一组已知最低点的小数据检查结果。
```

Goal 会让 Codex 持续朝这个完成条件推进，适合多步排错、迁移和资料整理；改一个错字用普通消息即可。桌面应用在输入框上方的目标进度行提供暂停、继续、编辑或清除入口，CLI 和 IDE 在交互会话中使用 `/goal`。

追加要求时在原聊天发送补充信息，不必再开一个相同目标。准备断网或休眠前先暂停，需要本机环境的工作不能因为开了 Goal 就脱离本机继续。功能没有出现时，先查当前版本与 [官方长任务说明](https://learn.chatgpt.com/docs/long-running-work)，不要照旧教程直接更改全部权限。

> **ps**：目标写成“生成哪些文件、通过什么检查”，比“继续努力直到最好”更容易判断何时结束。Goal 不会扩大原有文件、网络或远端账号权限。

## 八、侧聊与侧边栏

### 1. /side：顺手问一句，主任务继续做

主任务正在编译或整理资料，想了解某个选择的原因时，可在支持的 Codex 会话中输入：

```text
/side 解释一下当前方案为什么选择 Miniforge，以及与 Miniconda 的区别。
```

这会从当前聊天开启临时侧聊，侧聊记录与主聊天分开。问完返回主聊天；如果讨论结果需要改变实施方案，把最终要求明确发回主聊天，例如“后续统一用 Miniforge，修改相应安装步骤”。

侧聊适合澄清概念和查看思路，不要假设它的结论已自动成为主任务指令，也不要让它与主任务同时改同一批文件。`/side` 不能在已有侧聊里再次嵌套，review 模式也不可用，见 [官方命令说明](https://learn.chatgpt.com/docs/developer-commands#start-a-side-chat-with-side)。

### 2. 侧边栏：把经常继续的任务留在手边

在项目或聊天的菜单中置顶常用项，把标题改成具体结果，例如“GeTe 声子谱排错”，比“新聊天”容易找。完成的聊天可以归档，之后从设置中的已归档聊天入口恢复；入口名称随版本变化。

同一项工作尽量回到原聊天补充条件；独立任务再开新聊天。侧边栏置顶只是整理位置，不会把多个聊天的记录自动合并。操作见 [项目与聊天说明](https://learn.chatgpt.com/docs/projects)。

## 九、dot：持续跟进，再交给 Codex 动手

dot 是 ChatGPT 中持续跟进工作的一类代理，可以创建或继续 Codex 任务。它不是每个 Codex CLI 安装后就有的命令，账号开放情况见 [官方 dots 介绍](https://learn.chatgpt.com/docs/dots)。

### 第一次设置

1. 在 ChatGPT 桌面应用、手机应用或桌面浏览器找到 dots 入口，按引导创建并命名。没有入口时先核对账号开放范围和应用版本，企业工作区还可能需要管理员开启。
2. 只连接这项工作需要的插件；暂时不需要可跳过。需要使用本机项目时，在桌面应用的 dot 设置中连接电脑。
3. 先给一个范围明确的小任务，查看结果后再扩大。具体设置见 [dot 入门](https://learn.chatgpt.com/docs/dots/getting-started)。

例如可以让它跟进一组计算结果，把数据整理交给对应 Codex 项目：

```text
请跟进 GeTe 项目的计算结果：发现新完成的体积点时，
在已连接电脑的 GeTe 项目中创建 Codex 任务，汇总能量并更新能量—体积图。
保留原始数据，记录采用的能量定义和单位；结果整理完成或需要处理时通知我。
```

### 查看进度和停止

在 dot 资料页打开 `Activity` 查看它创建的任务，进入对应任务检查文件与结果；`Scheduled` 用于查看定时任务。需要停止时，主任务、委派任务和定时任务要分别核对，暂停 dot 主任务不代表其他任务都已停止，见 [dot 控制说明](https://learn.chatgpt.com/docs/dots/controls)。

dot 自己的云端工作可在本机关机后继续；调用本机文件、工具或本机 Codex 时，电脑仍需在线并保持 ChatGPT 应用打开。连接电脑也不会替你连接校园 VPN。集群监测仍须按 [SSH 与 VPN 条件](Codex连接科研集群（macOS）.md#vpn-与定时监测)准备，不把 dot 当作始终在线的集群登录节点。

## 十、几个顺手的小命令

下面在支持相应命令的 Codex 会话中输入，不是在 Bash 终端执行：

| 命令 | 什么时候用 |
| --- | --- |
| `/init` | 为项目生成 AGENTS.md 草稿，生成后检查并改成自己的约定 |
| `/review` | 修改结束后检查工作区中的潜在问题，再亲自查看差异和结果 |
| `/mcp` | 检查当前会话实际可用的 MCP 工具 |

先在输入框键入 `/` 查看当前可用项；详细用法见 [官方开发命令](https://learn.chatgpt.com/docs/developer-commands)。
